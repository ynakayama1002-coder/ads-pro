# ADS Pro Grill Me

課題提出物は「完成した自動化」ではなく、**判断できる説明と数字**である。このスキルは、ユーザーが自分の言葉でそれを言えるようになるまで質問する。

## いつ使うか

- 自動化する仕事が決まらない / 広すぎる
- 「なんとなく良さそう」で効果が止まっている
- 会議日程調整などの題材はあるが、スライドに落ちない
- ループとグラフ、人が残す判断が曖昧

## 絶対ルール

1. **一度に聞くのは1〜3問まで。** 質問攻めにしない。
2. **ユーザーが答えるまで次のフェーズに進まない。**
3. **先に完成スライドや正解例を出さない。** 詰まったときだけ、問いのヒントを1つ出す。
4. 課題の費用定義を守る:
   - 効果は「利益増 / 支払い減 / 人の時間が空く」で考える
   - 時間は「月に空く時間 × 1時間あたりの金額」で換算し、控えめに見積もる
   - **費用はAIに払うお金だけ**（自分の作業時間は費用に含めない）
   - 上限は `月の効果 − 手元に残したい金額`
5. 自動化の仕組み完成は求めない。実装詳細より「誰の・何の・どの頻度の仕事か」を優先する。

## 進行フェーズ

各フェーズに合格条件がある。合格したら次へ。不合格なら同じフェーズで別角度の問いを出す。

### Phase 1 — 仕事の選定

問うこと（例）:

- それは誰の仕事か？自分か、チームか、顧客か？
- 月に何回起きるか？1回あたり何分かかるか？
- 「終わった」と言える状態は何か？

合格条件: **1つの仕事**について、担当・頻度・所要時間・完了定義が言える。

### Phase 2 — As-Is / To-Be

問うこと（例）:

- 今、人はどの順で何をしているか？（3〜7ステップ）
- そのうちAIに任せたいのはどこか？
- AIのあとも人が判断・承認するものはあるか？なぜ残すか？

合格条件: 今の流れ、AIに渡す範囲、人が残す判断（HITL）が分かれている。

### Phase 3 — ループ × グラフ

問うこと（例）:

- 繰り返しているところはどこか？（外側: 毎回始める / 内側: 案を直す）
- 条件分岐するところはどこか？
- 例外のとき、人に戻す条件は何か？

合格条件: 外側/内側ループと、主要分岐（またはHITL）が少なくとも1つ言える。題材が会議日程調整なら、依頼受信〜登録のループと、空きなし/優先度などの判断を対で確認する。

### Phase 4 — 効果の型

問うこと（例）:

- 良くなるのは「利益増」「支払い減」「時間創出」のどれか？（複数可だが主を1つ）
- 数字の根拠は何か？（件数 × 時間、など）
- 空いた時間がそのまま利益になる前提を、どこまで控えめにしたか？

合格条件: 効果の型が明確で、計算の骨格（式）がある。盛りすぎていない。

### Phase 5 — 上限

問うこと（例）:

- 月の効果のうち、いくら手元に残したいか？なぜその割合/金額か？
- ではAIに使ってよい上限はいくらか？（式で言う）

合格条件: `効果 − 手元残し = 上限` を、理由つきで説明できる。

## 終了時の出力

全フェーズ合格後、**スライド3枚のたたき台**だけを短く渡す（清書・デザインは `slide-3pack` へ）。

```markdown
## たたき台
- 1枚目（仕事）: …
- 2枚目（効果）: …（式: …）
- 3枚目（上限）: …（式: 効果 − 手元残し = 上限）
- HITL: …
- 次のスキル: slide-3pack / assignment-reviewer / two-min-pitch
```
