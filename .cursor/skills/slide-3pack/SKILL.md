# Slide 3-Pack（統一HTML）

このスキルは **課題の3枚スライドを、リポジトリ内の統一デザインで作る** ことだけを担う。深掘り質問・提出レビュー・発表台本は扱わない。

## いつ使うか

- 仕事・効果・上限の素材が手元にあり、3枚に整形したい
- HTMLスライドを作りたい / 今後の課題でも同じ見た目にしたい
- Google スライド用の文言も欲しい（任意）

## デザイン（固定）

詳細: [DESIGN.md](DESIGN.md)

- **メイン:** Signal Numbers（案C）— 2・3枚目の数字を大きく
- **併用:** Split Frame（案B）— 左レールに枚番号と課題の問い
- テンプレ: `template/slide-3pack.html`（**単体HTML**。CSSは `<style>` 内包）
- テーマ原紙: `template/theme.css`（デザイン変更時の編集用。提出物にはコピーしない）

デザインを変えない。色・フォント・レール構成はテンプレ準拠のまま中身だけ差し替える。  
提出物は **`index.html` 1ファイルだけ** でブラウザから開けること。

## 絶対ルール

1. **本編は3枚。** 下表の3問をこの3枚で終える。Appendix（4枚目）は、下の「Appendix（4枚目）」のヒアリングで「作る」と答えたときだけ足す。聞かないまま足さない。作らないと決めた補足はスピーカーノートへ。
2. 各枚は課題の問いにだけ答える:

| 枚 | 問い（レール固定文言） | 書くこと |
| --- | --- | --- |
| 1 | どの仕事を、どう変えたいか | 今のやり方 / AIに任せたいところ / 人が残す判断 / **短いフロー1行**（`.flow`） |
| 2 | どれくらい良くなりそうか | 効果の型・計算式・控えめにした理由・**大数字** |
| 3 | AIにいくらまで使ってよいか | 上限の式・金額・手元残しの理由・**大数字** |

### 見せ方（B磨き・最小）

凝ったアニメや操作UIは作らない。次だけ守る。

- 1枚目: `依頼 → AIが… → 人が…` の短い `.flow` をタイトル直下に置く（図は足さない）
- 余白: `.main` の余白を広めに。本文は長くしすぎない（目安 1行あたり読み切り）
- 式: `.formula` に入れ、先頭に `.formula-label`（計算 / 上限の式）を付ける
- 2・3枚目: `.signal` の金額が一目で最大要素になること

3. 費用は **AIに払うお金だけ**。自分の制作時間は費用に入れない。
4. 知らない人でも分かる語で書く。社内用語は括弧で一言補う。
5. 実装詳細・技術スタックの羅列はしない。
6. 数字には「式」または「件数×時間」などの根拠を添える。

## Appendix（4枚目）

本編の3枚は崩さない。次のどれかがあるときだけ、**作る前に**聞く。どれも無いときは聞かない。

- 課題文が 3〜4 枚、または任意の追加枚を書いている
- 骨子に、本編に入りきらない対比がある（変更前、これから、聞かれたとき）
- ユーザーが補足、Appendix、4枚目と言った

### ヒアリング

推測で枚を足さない。次の3つだけ聞く。

1. Appendix を作るか。作らないなら、その内容はスピーカーノートだけにする
2. 作るなら、スライドに出す文は何か。ノートだけに残す文は何か
3. 制限時間の本編に含めるか、聞かれたときの補足か

聞き手が読む文を、ノートにだけ書いて終えない。ノートは口頭の補足に使う。

### 作ると答えたとき

- 見た目は本編と同じ（色、フォント、左レール、16:9、単体 HTML）。レールの文言は `Appendix`
- トークン対効果の4問目は作らない。大数字は必須にしない
- 構成図や対比を置くときは、図でその枚を埋めない。余白が残るなら字を小さくして、フォルダ名と中身のような具体を残す
- 折り返しは本編と同じ。意味の途中で折れそうな行だけ聞き、`<br>` で明示する
- 本編の制限時間は崩さない。ノートに「本編は1〜3枚。Appendix は補足」と書く

## 必要な入力

次が欠ける場合は **推測で埋めず、不足項目だけ質問する**（別スキルへ誘導しない）:

- 仕事の名前と今の流れ
- AIに任せること / 人が残す判断
- 月の件数・1件あたり時間・換算単価（または効果金額とその式）
- 手元に残したい額（または残し率）

## 出力手順（必須）

1. `template/slide-3pack.html` を提出用パスへコピーする  
   例: `lectures/1st/monthly-assignment/deliverables/slides/index.html` および分かりやすい別名（例: `会議日程調整_スライド.html`）  
   - **CSSは既にHTML内に埋め込み済み。`theme.css` を横に置かない。**
   - ブラウザ単体で開けること（`file://` でも可）。外部CSS依存は禁止。
2. HTML のスロット（`<!-- S1_TITLE -->` など）を実データで埋める  
   - スライド1の `.flow` に変更後の短い流れ（3ステップ程度）  
   - スライド2の `.signal` に効果金額  
   - スライド3の `.signal` に上限金額  
   - レールの問い文言はテンプレのまま（課題の3問と一致）
3. **Appendix のヒアリング**  
   上の「可能性がある」に当たるときだけ、折り返し確認より先に聞く。答えが出るまで4枚目を作らない。当たらないときは聞かない。
4. **折り返し確認（必須・1〜3問）**  
   草稿を出したあと、推測で改行せずに聞く。既定は「横幅を使ってなるべく1行」。意味の途中で切れそうな行だけ選択肢を出す。  
   例:
   - 長い「今:」行 → 切らない / どこで改行 / 短く言い換え
   - 式 → 1行のまま / `＝` の前で改行
   - 長い理由 → 1行のまま / `／` や句点の前で改行  
   回答は `<br>` など**明示改行**で入れる。CSSの狭い `max-width` で勝手に折らない。
5. `index.html` 単体をブラウザで開き、本編3枚・フロー・式・ノート・折り返しを確認する。Appendix があるときは、ヒアリングの答えと、図が本編の主張を埋めていないことを確認する
6. チャットでは、保存先パスと操作（←→ / `N` でノート）を短く伝える

デザインを直すときは `template/theme.css` を編集し、その内容をテンプレHTMLの `<style>` に再反映してから提出物を作る。
