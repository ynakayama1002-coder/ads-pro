# Slide 3-Pack（Google スライド）

月次課題「AI自動化とトークン対効果」の提出用に、**ちょうど3枚**のスライド原稿を作る。作成先は **Google スライド**。

## いつ使うか

- `ads-pro-grill-me` などで仕事・効果・上限が固まったあと
- 既存メモを3枚構成に整形したいとき
- Google スライド用の文言・構成がほしいとき

## 絶対ルール

1. **枚数は3枚固定。** 4枚目以降を足さない。補足はスピーカーノートへ。
2. 各枚は課題の問いにだけ答える:

| 枚 | 問い | 書くこと |
| --- | --- | --- |
| 1 | どの仕事を、どう変えたいか | 今のやり方 / AIに任せたいところ / 人が残す判断 |
| 2 | どれくらい良くなりそうか | 効果の型・計算式・控えめにした理由 |
| 3 | AIにいくらまで使ってよいか | 上限の式・金額・手元残しの理由 |

3. 費用は **AIに払うお金だけ**。自分の制作時間は費用に入れない。
4. 知らない人でも分かる語で書く。社内用語は括弧で一言補う。
5. 実装詳細・技術スタックの羅列はしない（課題は仕組み完成を求めていない）。
6. 数字には必ず「式」か「件数×時間」などの根拠を添える。

## 入力が足りないとき

次が欠ける場合は推測で埋めず、不足だけ確認する（または `ads-pro-grill-me` を案内する）:

- 仕事の名前と今の流れ
- 月の件数・1件あたり時間・換算単価
- 手元に残したい額（または残し率）
- 人が残す判断（なければ「例外時のみ確認」など明示）

## 出力フォーマット

次の順で出す。

### A. スライド原稿（コピー用）

各枚について:

```markdown
## スライド1 — どの仕事を、どう変えたいか
### タイトル
（12〜28字程度）

### 本文（画面に出す）
- 今: …
- AIに任せる: …
- 人が残す: …

### スピーカーノート（2分用・口語）
…
```

スライド2・3も同型。スライド2には **式**、スライド3には **`月の効果 − 手元残し = 上限`** を必ず含める。

### B. Google スライドへの反映手順

1. [Google スライド](https://slides.google.com) で新規プレゼンを作る（または既存を開く）
2. テーマはシンプル（文字が大きく読めるもの）。装飾より可読性
3. スライドを3枚にする（余分は削除）
4. 各枚に「タイトル」と「本文の箇条書き」を貼る
5. **スピーカーノート**に口語ノートを貼る（表示 → スピーカーノート）
6. 画面共有しても読めるよう、本文は1枚あたり箇条書き3〜5行、文字大きめ

Google スライド操作をエージェントが代行できる環境なら、ユーザー確認のうえ作成・追記してよい。できない場合は、上記のコピー用テキストと手順を渡す。

### C. 貼り付け用プレーンテキスト

Google スライドのタイトル欄・本文欄にそのまま貼れるよう、装飾の少ない版も併記する。

```text
【スライド1タイトル】
...
【スライド1本文】
...
【スライド1ノート】
...
```

## レイアウト指針（Google スライド）

- 1枚1メッセージ。タイトルが問いまたは結論
- 本文は箇条書き。長文段落はノートへ
- スライド2・3の数字は太字や大きめの一語で視線誘導してよいが、派手な装飾は不要
- 例示の飲食店発注と並べる必要はない。ユーザーの仕事だけを書く

## 作り終えたら必ず自己確認

- [ ] 仕事を知らない人にも、今のやり方と変えたいところが伝わるか
- [ ] 効果と上限の数字を、なぜその数字にしたか説明できるか
- [ ] 3枚以外に本編スライドを増やしていないか

確認後、`assignment-reviewer` と `two-min-pitch` への引き継ぎを一文で案内する。
