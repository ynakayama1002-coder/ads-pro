# Slide 3-Pack（統一HTML）

このスキルは **課題の3枚スライドを、リポジトリ内の統一デザインで作る** ことだけを担う。深掘り質問・提出レビュー・発表台本は扱わない。

## いつ使うか

- 仕事・効果・上限の素材が手元にあり、3枚に整形したい
- HTMLスライドを作りたい / 今後の課題でも同じ見た目にしたい
- Google スライド用の文言も欲しい（任意）

## デザイン（固定）

詳細: [DESIGN.md](DESIGN.md)

- **メイン:** Signal Numbers（案C）— 2・3枚目の数字を大きく
- **併用:** Split Frame（案B）— 左レールに枚番号と課題の問い
- テンプレ: `template/slide-3pack.html`（**単体HTML**。CSSは `<style>` 内包）
- テーマ原紙: `template/theme.css`（デザイン変更時の編集用。提出物にはコピーしない）

デザインを変えない。色・フォント・レール構成はテンプレ準拠のまま中身だけ差し替える。  
提出物は **`index.html` 1ファイルだけ** でブラウザから開けること。

## 絶対ルール

1. **枚数は3枚固定。** 4枚目以降を本編に足さない。補足はスピーカーノートへ。
2. 各枚は課題の問いにだけ答える:

| 枚 | 問い（レール固定文言） | 書くこと |
| --- | --- | --- |
| 1 | どの仕事を、どう変えたいか | 今のやり方 / AIに任せたいところ / 人が残す判断 |
| 2 | どれくらい良くなりそうか | 効果の型・計算式・控えめにした理由・**大数字** |
| 3 | AIにいくらまで使ってよいか | 上限の式・金額・手元残しの理由・**大数字** |

3. 費用は **AIに払うお金だけ**。自分の制作時間は費用に入れない。
4. 知らない人でも分かる語で書く。社内用語は括弧で一言補う。
5. 実装詳細・技術スタックの羅列はしない。
6. 数字には「式」または「件数×時間」などの根拠を添える。

## 必要な入力

次が欠ける場合は **推測で埋めず、不足項目だけ質問する**（別スキルへ誘導しない）:

- 仕事の名前と今の流れ
- AIに任せること / 人が残す判断
- 月の件数・1件あたり時間・換算単価（または効果金額とその式）
- 手元に残したい額（または残し率）

## 出力手順（必須）

1. `template/slide-3pack.html` を提出用パスへコピーする（例: `2026年11月/月次課題/slides/index.html`）  
   - **CSSは既にHTML内に埋め込み済み。`theme.css` を横に置かない。**
2. HTML のスロット（`<!-- S1_TITLE -->` など）を実データで埋める  
   - スライド2の `.signal` に効果金額  
   - スライド3の `.signal` に上限金額  
   - レールの問い文言はテンプレのまま（課題の3問と一致）
3. `index.html` 単体をブラウザで開き、3枚・式・ノートを確認する
4. チャットでは、保存先パスと操作（←→ / `N` でノート）を短く伝える

デザインを直すときは `template/theme.css` を編集し、その内容をテンプレHTMLの `<style>` に再反映してから提出物を作る。

### 任意: Google スライド用テキスト

ユーザーが求めたときだけ、同じ内容の貼り付け用プレーンテキストも併記する。HTMLが主成果物。

```text
【スライド1タイトル】
...
【スライド1本文】
...
【スライド1ノート】
...
```
