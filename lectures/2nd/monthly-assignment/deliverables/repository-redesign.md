# ADS-Pro リポジトリ再設計書

## 1. 目的

ADS-Proリポジトリを、講義資料や課題を保管するだけの場所から、AIエージェントが継続的に参照・分析・活用できる学習基盤へ再設計する。

単純なフォルダ整理にとどまらず、今後のAIエージェント活用を見据えた情報設計と運用ルールを整備する。

### 設計方針

1.  **SSoT（Single Source of Truth）**：情報の正本を明確にする。
2.  **Progressive
    Disclosure**：AIが必要な情報だけを段階的に参照できるようにする。
3.  **Separation of Concerns**：情報の役割を分離する。
4.  **Traceability**：情報の出所と変更経緯を追跡できるようにする。
5.  **Human in the Loop**：AIによる変更を人間が確認する。
6.  **Tool Agnostic**：特定のAIツールに依存しない構成にする。

### 2.2 ディレクトリ・ファイルの役割

  ディレクトリ・ファイル   役割
  ------------------------ ------------------------------------
  `README.md`              人間向けのリポジトリ案内・利用方法
  `AGENTS.md`              AIエージェント共通の作業指示
  `program.md`             ADS-Pro全体の目的・対象・学習方針
  `lectures/`              各講義の資料・課題・成果物
  `group-sessions/`        グループセッションの資料・課題

### 2.3 フォルダ設計の考え方

-   講義とグループセッションを分離する。
-   それぞれの回を番号付きフォルダで管理する。
-   各回の中では、講義資料と課題を分離する。
-   課題の成果物は、その課題の配下に保存する。
-   不必要に階層を深くしない。
-   空のフォルダや、将来使うかもしれないだけのフォルダは作らない。

## 3. 主要ファイルの設計

### 3.1 `README.md`：人間向けの入口

README.mdは、リポジトリを初めて見る人が全体像を把握するための案内とする。

記載内容：

-   ADS-Proの概要
-   リポジトリの目的
-   ディレクトリ構成
-   各フォルダの役割
-   資料の参照方法
-   AIツールを利用する際の基本的な案内

README.mdに詳細な運用ルールや講義内容を重複して記載しない。

### 3.2 `AGENTS.md`：AIへの共通指示

AIエージェントがリポジトリ内で作業する際の共通ルールを定義する。

#### 基本方針

-   作業開始前に`program.md`を確認する。
-   情報の正本を尊重する。
-   同じ情報を複数箇所に作らない。
-   不明な情報を推測で補完しない。
-   既存の資料や成果物を無断で削除・変更しない。

#### 情報の参照ルール

-   講義内容の分析では、対象回の`lecture-material/`を参照する。
-   課題対応では、対象回の`monthly-assignment/`を参照する。
-   グループセッションに関する作業では、対象回の`group-sessions/`配下を参照する。
-   作業に必要な情報だけを読み込む。
-   他の回の資料を参照する場合は、その必要性を判断する。

#### 情報の更新ルール

-   講義文字起こしなどの原資料は原則として変更しない。
-   課題の正式要件は原本を維持する。
-   要約や分析結果は原資料と区別して保存する。
-   情報の更新時には、関連ファイルへの影響を確認する。
-   AIが作成した内容は、人間の確認を経て確定する。

#### 作業完了時の報告

-   変更したファイルを列挙する。
-   変更理由を説明する。
-   重複や矛盾が発生していないか報告する。
-   未確認事項や判断が必要な事項を明示する。

### 3.3 `program.md`：プロジェクトの全体像

ADS-Proの目的や学習方針を定義するファイル。

  項目       記載内容
  ---------- ----------------------------------
  目的       ADS-Proを通じて実現したい状態
  対象者     受講者の職位・経験・知識レベル
  期間       プログラムの実施期間
  回数       講義・グループセッションの回数
  時間       各回の実施時間
  学習方針   どのような考え方で学習を進めるか
  学習内容   各回の学習テーマの概要

`program.md`はADS-Pro全体の方針を示す正本とする。各回の詳細な講義内容や課題要件は、個別の講義フォルダに記載する。

## 4. 情報管理のルール

### 4.1 情報の正本（SSoT）

同じ情報を複数のファイルで管理しない。

  情報                      正本
  ------------------------- ------------------------
  ADS-Pro全体の目的・方針   `program.md`
  講義の文字起こし          各回の`transcript.md`
  授業内メモ                各回の`class-notes.md`
  課題の正式要件            各回の`assignment.md`
  発表資料などの成果物      各回の`deliverables/`

README.mdやAGENTS.mdには、これらの情報を複製せず、必要な参照先を案内する。

### 4.2 原資料とAI生成物の分離

以下を区別する。

-   **原資料**：講義文字起こし、授業内メモ、正式な課題内容
-   **AI生成物**：要約、分析、改善案、発表資料、作業計画
-   **確定情報**：人間が内容を確認し、正式に採用した情報

AI生成物を原資料の代わりに扱わない。

### 4.3 情報の更新

-   過去の変更履歴はGitに任せる。
-   現在有効な情報を各正本に反映する。
-   古い情報を残す場合は、現行情報と区別する。
-   進捗管理をMarkdownファイルとGitHub Projectsなどで二重管理しない。

## 5. AIエージェント活用を見据えた設計

### 5.1 ツール非依存の原則

Cursorだけでなく、Claude
Codeなど複数のAI開発ツールから利用できる構成を目指す。

-   プロジェクト共通ルールは`AGENTS.md`に集約する。
-   特定ツール専用の設定や機能は、ツール固有のディレクトリに配置する。
-   共通ルールとツール固有ルールを重複させない。
-   特定ツールでしか実行できない処理を共通ルールに混在させない。

既存の`.cursor/skills/`はCursor固有の資産として維持する。

将来的に複数ツールで共通利用するスキルを整備する場合は、スキルの共通仕様と各ツールの対応状況を確認したうえで配置方法を決定する。現段階では、既存スキルを無理に移動・統合しない。

### 5.2 将来的なAIエージェント構想

  エージェント          役割
  --------------------- --------------------------------------
  Repo Auditor          リポジトリ構成、重複、古い情報を検査
  Lecture Analyst       講義内容の要約・分析
  Assignment Planner    課題の分解と実施計画の作成
  Knowledge Curator     複数講義から再利用可能な知識を整理
  Slide Creator         発表資料の構成・作成
  Assignment Reviewer   課題成果物のレビュー

これらは将来構想であり、今回の作業で一括実装しない。まずは情報構造と共通ルールを整備し、AIが適切に情報を参照できる状態を作る。

### 6.2 移行方針

  現状                        移行後                       対応
  --------------------------- ---------------------------- --------------------
  `1st lecture/`              `lectures/1st/`              移動
  `2nd lecture/`              `lectures/2nd/`              移動
  `3rd〜13th lecture/`        `lectures/3rd〜13th/`        移動
  `1st group-session/`        `group-sessions/1st/`        移動
  `2nd〜6th group-session/`   `group-sessions/2nd〜6th/`   移動
  `README.md`                 `README.md`                  内容を整理
  `引き継ぎ.md`               各情報の正本へ分割           内容を精査して移管
  `.cursor/skills/`           `.cursor/skills/`            原則維持

### 6.3 ファイル名の統一

可能な範囲で、ファイル名は半角英小文字とハイフンを基本とする。

  現状の名称                  移行後
  --------------------------- ------------------
  `第2回講義_文字起こし.md`   `transcript.md`
  `授業内メモ.txt`            `class-notes.md`
  `課題内容.txt`              `assignment.md`

単純な名称変更だけでなく、ファイルの内容と役割を確認してから実施する。原資料の内容は変更しない。文字起こしの誤記修正なども今回の移行作業には含めない。

### 6.4 `引き継ぎ.md`の整理

引き継ぎ.mdには複数の役割が混在しているため、内容を精査して適切な場所へ移管する。

-   プロジェクトの目的・方針 → `program.md`
-   リポジトリの使い方 → `README.md`
-   AIへの共通指示 → `AGENTS.md`
-   過去の変更履歴 → GitHubの履歴
-   今後の作業予定 → 必要に応じてGitHub Issues等

移管先が明確でない情報は、推測で削除・移動せず、判断事項として残す。

## 10. 設計上の最終判断

今回の再設計では、AIエージェントを増やすことよりも、AIが正しい情報を参照できる土台を作ることを優先する。

特に重要なのは次の3点。

1.  **情報の置き場所を明確にする。**\
    AIがどこを見ればよいか迷わない構成にする。

2.  **情報の正本を明確にする。**\
    同じ情報が複数の場所に存在し、AIが異なる情報を参照する状態を防ぐ。

3.  **AIツールに依存しない。**\
    CursorやClaude
    Codeなど、利用するツールが変わってもプロジェクトの情報設計と基本ルールを維持できるようにする。

今回のゴールは、単に整理されたリポジトリではなく、今後のAI活用を受け入れられるリポジトリの基盤を作ることである。
